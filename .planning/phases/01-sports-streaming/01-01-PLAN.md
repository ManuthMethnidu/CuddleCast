# Plan 01-01: Core Sports Types, OpenF1 & Jolpica API Integration, and High-Fidelity Autonomous Track Simulator Fallback Engine

<objective>
Implements D-04: Hybrid OpenF1 + Jolpica/Ergast API Integration and D-05: Track Simulator Fallback. Establish foundational data contracts, real-time F1 API clients, and the 24/7 high-fidelity circuit simulator engine.
</objective>

## Plan Overview
Establish the foundational data contracts, real-time F1 API clients, and the 24/7 high-fidelity circuit simulator engine. This enables real-time telemetry (laps, gap intervals, tire compounds, car sensor metrics, and DRS actuation) during live Grand Prix weekends while ensuring the UI is never blank or static between races by falling back to a deterministic, physics-grounded 20-car simulation engine.

---

## Must-Haves
<must_haves>
### Truths
- `src/types/sports.ts` declares comprehensive, strongly-typed domain interfaces for motorsport sessions, series metadata, stream channels, OpenF1 telemetry, Jolpica championship standings, tyre compounds, and circuit telemetry snapshots.
- `src/services/openf1.ts` provides typed, resilient fetch methods for OpenF1 endpoints (`/meetings`, `/sessions`, `/drivers`, `/intervals`, `/stints`, `/car_data`, `/weather`) with in-memory caching and graceful fallback on empty/off-track data.
- `src/services/jolpica.ts` provides typed fetchers for Ergast/Jolpica 2026 season calendar (`/current.json`), driver standings (`/current/driverStandings.json`), and constructor standings (`/current/constructorStandings.json`).
- `src/services/circuitSimulator.ts` runs an autonomous 20-car 2026 grid simulation loop (~1 Hz ticks) that calculates sector timing deltas (S1/S2/S3), realistic tyre degradation curves (Soft, Medium, Hard), DRS zone activation when gap $\le$ 1.0s, and pit stop time loss (~21.5s).

### Edge Coverage
- Handled empty OpenF1 live responses when no live session is currently active by transitioning smoothly to simulated data.
- Handled network disconnection or rate-limiting from upstream APIs without throwing unhandled exceptions.
- Throttled simulation updates to avoid CPU thrashing when the browser tab is hidden or backgrounded (`document.hidden`).

### UI Considerations
- Telemetry numbers (speeds, lap times, gaps) must be strictly formatted for monospace display (`ui-monospace, monospace`, weight 600) matching `01-UI-SPEC.md`.
- Tyre compounds strictly correspond to official colors: Soft (`#FF3333`), Medium (`#FFD700`), Hard (`#FFFFFF`), Intermediate (`#39B54A`), Wet (`#0099FF`).

### Artifacts this phase produces
- `src/types/sports.ts` (Interfaces: `MotorsportSession`, `StreamChannel`, `SeriesMeta`, `SessionState`, `OpenF1Meeting`, `OpenF1Session`, `OpenF1Driver`, `OpenF1Interval`, `OpenF1Stint`, `OpenF1CarData`, `OpenF1Weather`, `JolpicaCalendarResponse`, `JolpicaStandingsResponse`, `DriverTiming`, `TelemetrySnapshot`, `TyreCompound`)

</must_haves>

## Threat Model
<threat_model>
### Security Capabilities
- **T-01-01 (Malicious API Responses / Prototype Pollution):** Untrusted or malformed JSON payloads returned from external public REST endpoints (`api.openf1.org`, `api.jolpi.ca`).
  * *Mitigation:* Explicit response schema validation and defensive parsing. Strict numerical sanitization (`Number.isFinite`, fallback defaults) before passing speed, RPM, or lap times into calculations or React state.
- **T-01-02 (CORS / Leaked Credentials):** Requests to public APIs leaking private cookies or auth headers.
  * *Mitigation:* Ensure all fetch requests to OpenF1 and Jolpica are anonymous, omitting credentials (`credentials: 'omit'`) and explicitly requesting `application/json`.
- **T-01-03 (Memory Exhaustion / Event Loop Starvation):** Unbounded interval timers and high-frequency 3.7Hz telemetry polling leaking memory or overloading the single-threaded JS runtime.
  * *Mitigation:* Simulator ticker uses bounded circular buffers, subscriber cleanup callbacks, and pauses updates when `document.hidden === true`.
</threat_model>
